# Modelo de dados

Fonte da verdade: os modelos em `backend/app/models/` e as migrações Alembic em
`backend/migrations/versions/` (migrações: `0001_initial`, `0002_obras_acc_item_name`, `0003_obras_active_webhook_obra`, `0004_elements_name`, `0005_version_reports`, `0006_search`, `0007_param_defs_unique_ci`, `0008_reconcile`, `0009_unaccent`, `0010_obra_mark_rule`, `0011_assemblies`, `0012_obra_params`, `0013_piece_props`, `0014_saved_filters`). Um teste
(`tests/test_migrations.py::test_models_match_migrations`) falha se modelos e
migração divergirem.

## Convenções

- Chaves primárias `id BIGINT GENERATED BY DEFAULT AS IDENTITY`.
- Datas com fuso: `TIMESTAMPTZ`, padrão `now()`.
- **Colunas de autoria** (`created_at`, `updated_at`, `created_by`, `updated_by`) em todas
  as tabelas editáveis. `created_by`/`updated_by` → `users.id` (`ON DELETE SET NULL`);
  nulo significa ação do sistema.
- Domínios como `VARCHAR` + `CHECK` (mais fácil de evoluir que tipos ENUM do Postgres).
- Nomes de constraints estáveis: `pk_<tabela>`, `fk_<tabela>_<coluna>_<ref>`,
  `uq_<tabela>_<colunas>`, `ix_<tabela>_<colunas>`, `ck_<tabela>_<regra>`.
- Dados da fábrica nunca são apagados em cascata: só `elements` (dados do BIM,
  recriáveis a partir do Docs) usa `ON DELETE CASCADE`.
- Toda escrita de serviço chama `app.services.audit.record(...)` na mesma transação.

## Tabelas

| Tabela | Colunas | Regras |
|---|---|---|
| **users** | id, name, email, role, active, autoria | `uq_users_email`; `role ∈ {projetos, fabrica, admin, leitura}` |
| **obras** | id, code, name, acc_hub_id, acc_project_id, acc_folder_id, acc_item_id, acc_item_name, active, mark_property_names JSONB, category_property_names JSONB, autoria | `uq_obras_code`; `mark_property_names`/`category_property_names`: regra de identificação da obra (lista em ordem de prioridade; nulo = padrão do servidor); `active` (padrão true): obras inativas saem da verificação periódica; `acc_item_name` é só para exibição (nome do arquivo no Docs, conferido no vínculo) |
| **model_versions** | id, obra_id, acc_version_id, version_number, urn, status, published_by, published_at, comment, error, autoria | `uq_model_versions_acc_version_id`; `status ∈ {pending, translating, processing, ready, failed, no_translation}` (padrão `pending`); índice (obra_id, version_number); `published_by` é o nome vindo do ACC (texto, não FK) |
| **elements** | id, version_id, external_id, dbid, name, mark_raw, category, level, search_text, props JSONB, mark_id, created_at | `uq_elements_version_id_dbid`; índice (version_id, external_id); índice mark_id; índice (version_id, level); `level` vem de `LEVEL_PROPERTY_NAMES`; `search_text` = nome, categoria, marca, nível e valores de `SEARCH_PROPERTY_NAMES` (busca livre); **índice GIN `ix_elements_props_gin` em props** (consultas `props @> {...}`); FK version_id `CASCADE`, mark_id `SET NULL` |
| **version_diffs** | id, version_id, prev_version_id, diff JSONB, autoria | `uq_version_diffs_version_id`; FK version_id `CASCADE`, prev_version_id `SET NULL`. Conteúdo: `totals` por classe (unchanged, count_changed, changed, new, removed), `review`, `orphans`, `returned`, `review_properties`, `marks[]` (não inalteradas: código, categoria, classe, contagens, diffs, nota, `has_values`, `action`) |
| **version_reports** | id, version_id, report JSONB, autoria | `uq_version_reports_version_id` (um relatório por versão, substituído ao reprocessar); FK version_id `CASCADE` (dado derivado do BIM, recriável). Conteúdo: `config`, `totals` (pieces, marks, without_mark, inconsistent_marks, by_category), `without_mark[]`, `inconsistent[]` |
| **version_property_names** | version_id, group_name, prop_name | PK (version_id, group_name, prop_name); FK version_id `CASCADE`. Grupos em que cada propriedade existe na versão: o filtro `Nome=valor` vira `props @> {"Grupo": {"Nome": valor}}` (índice GIN). Derivada do BIM, recriada no processamento; como `elements`, sem colunas de autoria |
| **marks** | id, obra_id, code, category, review_status, review_note, autoria | **`uq_marks_obra_id_code_category`** (MARCA = obra + código + categoria); `review_status ∈ {ok, review}` (padrão `ok`; `review` = mudou na versão nova e tem valores, com `review_note` = diff), índice parcial `ix_marks_obra_id_review` |
| **param_defs** | id, name, type, unit, options JSONB, required, categories JSONB, scope, obra_id, active, autoria | `type ∈ {text, number, list, date, bool}`; `scope ∈ {global, obra}`; `scope = obra` ⇔ `obra_id` preenchido; nome único **sem diferenciar maiúsculas entre os ativos** (`lower(name)`; índices parciais `uq_param_defs_global_name` e `uq_param_defs_obra_name` com `AND active`); o serviço também impede que um global repita o nome de um parâmetro de obra (e vice-versa); excluir = `active=false`; `categories` nulo = todas |
| **param_values** | id, mark_id, def_id, value JSONB, **row_version**, autoria | **`uq_param_values_mark_id_def_id`**; `value` nulo = apagado; `row_version` (inicia em 1) é o `version_id_col` do SQLAlchemy: todo UPDATE leva `WHERE row_version = <lido>` e incrementa; conflito → `StaleDataError` (concorrência otimista) |
| **orphans** | id, mark_id, since_version_id, status, relinked_to, autoria | `status ∈ {open, relinked, archived, returned}` (padrão `open`; `returned` = a marca voltou numa versão seguinte); no máximo um órfão `open` por marca (`uq_orphans_open_mark_id`) |
| **saved_filters** | id, name, scope, owner_id, obra_id, definition JSONB, system_key, autoria | `scope ∈ {personal, shared}`; `personal` exige `owner_id` (FK users `CASCADE`); `obra_id` nulo = todas as obras (FK `CASCADE`); nome único sem diferenciar maiúsculas **por escopo** (`uq_saved_filters_shared_name` entre os compartilhados; `uq_saved_filters_personal_name` por dono); `definition` no formato do motor (`mode/logic/rules`); `system_key` (único) marca os filtros de sistema, sempre compartilhados: `pending`, `partial`, `review`, `new`, `orphans` (seed da `0014`) |
| **color_schemes** | id, name, scope, owner_id, obra_id, rules JSONB, autoria | Mesmas regras de escopo, dono, obra e nome de `saved_filters`; `rules` = lista ordenada `[{filter: <id de saved_filters> \| <definição>, color: "#RRGGBB", label}]` (a primeira regra que bate vence). Excluir um filtro usado num esquema dá 409 |
| **audit_log** | id, entity, entity_id, action, before JSONB, after JSONB, user_id, batch_id UUID, at | índices (entity, entity_id), batch_id, at; `entity_id` é texto para aceitar qualquer chave |
| **webhook_events** | id, event_id, payload JSONB, obra_id, received_at, processed_at | `uq_webhook_events_event_id` (idempotência: header de entrega ou SHA-256 do corpo); `obra_id` → obras (`SET NULL`), índice; `processed_at` preenchido pelo job `sync_obra` |

## O que mudou em relação ao modelo inicial

- Fase 2 (`0002`): `obras.acc_item_name`.
- Fase 2 (`0003`): `obras.active`, `webhook_events.obra_id`.
- Fase 3 (`0004`): `elements.name` (nome do elemento no modelo). `elements.mark_raw` guarda a marca como está no modelo (sem espaços nas pontas); `marks.code` é a forma normalizada (trim + maiúsculas).
- Fase 3 (`0005`): tabela `version_reports` (relatório de validação de marcas por versão).
- Fase 7 (`0008`): domínio de `marks.review_status` → `{ok, review}`; `orphans.status` + `returned`; tabela `version_diffs`. Auditoria: `mark` (`review`, `review_keep`, `review_resolved`, `review_restored`), `orphan` (`create`, `returned`, `relink`, `archive`) e `mark_value` com `source: relink`.
- Fase 6 (`0007`): unicidade de `param_defs.name` por `lower(name)` e só entre ativos (um nome excluído pode ser recriado).
- Busca (`0009`): extensão `unaccent` e função `f_unaccent(text)` IMMUTABLE (busca sem acentos).
- Identificação (`0010`): `obras.mark_property_names`, `obras.category_property_names`. Auditoria: `obra` / `mark_rule`; órfã criada pela troca de regra tem `reason: mark_rule`.
- Motor de filtros (`0013`): tabela derivada `piece_props` (version_id, piece_id → elements CASCADE, mark_id, source model|factory|system, key, value_text ≤ 500, value_num, value_date), com índices `(version_id, source, key, value_text|value_num|value_date)`, `(piece_id)` e `(mark_id, source)`. `version_property_names` ganha `value_type`, `pieces` e `distinct_values`. Backfill: `python -m app.cli piece-props backfill --all`.
- Filtros salvos e cores (`0014`): tabelas `saved_filters` e `color_schemes`. Os atalhos da busca viraram filtros de sistema (`system_key`). Status de produção, "Nova na versão" e "Órfã" são campos de sistema **calculados na hora** pelo motor (não dependem de `piece_props`).
- Biblioteca por obra (`0012`): tabela `obra_params` (obra_id, def_id, created_at, created_by; PK composta). Um parâmetro global (biblioteca) só vale para as obras em que foi incluído. Backfill: incluído onde já havia valores. Auditoria `obra_param` (`include`, `exclude`); retirar não apaga valores.
- Montagens (`0011`): `obras.piece_category_names` (modo montagens do .nwd/.rvt; nulo = desligado), `elements.member_dbids` JSONB com índice GIN `jsonb_path_ops` (dbIds dos membros e da geometria da peça).
- Fase 5 (`0006`): `elements.level`, `elements.search_text` (backfill básico: nome, categoria, marca; reprocessar a versão completa) e tabela `version_property_names`.

- Acrescentadas as colunas de autoria (`created_at/updated_at/created_by/updated_by`) em
  users, obras, model_versions, marks, param_defs, param_values e orphans.
  `elements` tem só `created_at`. `audit_log` e `webhook_events` têm só os próprios carimbos.
- `marks.review_status` ganhou domínio: `pending | ok | issue`.
- `param_values.row_version` passou a controlar a concorrência otimista.
- Auditoria dos valores da fábrica (6.2/6.3, sem migração): `entity="mark_value"`, `entity_id` = id da marca, `before/after` = `{mark_id, mark, def_id, param, value}`. Um `batch_id` por salvamento ou lote. Linhas da edição em lote levam `"source": "batch"`; as do desfazer, `"source": "undo"` e `"undo_of": <batch_id>` (é assim que se sabe que um lote já foi desfeito).
- Unicidades e índices listados acima, incluindo os índices parciais de `param_defs` e `orphans`.
- `param_values.mark_id`, `orphans.*` e `param_defs.obra_id` usam `RESTRICT`: apagar uma marca ou uma obra com dados da fábrica falha em vez de apagar em silêncio.
